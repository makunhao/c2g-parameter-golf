## 二、这份交付里最硬的东西是什么

不是方案文档，是**三件实测出来的事**：

### 2.1 官方 BPB 口径被抄准了（残差 −1 字节 / 231,896 = 0.0004%）

BPB 挂在 35% 上，口径错了后面全白做。我从 `train_gpt.py` 抽出
`eval_val()` 与 `build_sentencepiece_luts()`，加了一条**可判真假的恒等式**
（Σ逐 token 字节 == 文本字节数），排查三轮后收敛到 **−1 字节**：

| 层 | 差多少 | 根因 |
|---|---|---|
| 1 | numpy 广播报错 | 我的 bug：官方评测里第 0 个 token 不是 target |
| 2 | 30,827 字节 | **我的自检前提错了**：SentencePiece 会折叠空白（代码语料缩进多） |
| 3 | 21 字节 | 4 个 `<unk>` token——官方**故意**给它们记 0 字节 |
| 4 | **−1 字节** | `add_dummy_prefix`，第 0 个 token 前驱按边界处理 |

> 小样本交叉验证：`"hello world"` 11/11/11，`"The weight decay"` 16/16/16，**完全相等**。

### 2.2 tokens/byte 的机制被验证了（−23.9%）

同一语料自训两套 BPE：

| vocab | tokens/byte | 相对 |
|---|---|---|
| 1024 | 0.4196 | — |
| 4096 | **0.3193** | **−23.9%** |

### 2.3 先给可被证伪的判据，再看数据——**结果推翻了预测**

由 BPB 定义式推出：

> **BPB₄₀₉₆ < BPB₁₀₂₄ ⟺ L₄₀₉₆/L₁₀₂₄ < 0.4196 / 0.3193 = 1.3142**

（理由：4096 输出类别多 4 倍，均匀分布下交叉熵上界是 `ln4096/ln1024 = 1.200`。
所以只要涨幅低于 31.4%，换 tokenizer 就是赚的。）

**实测（800 步 × 3 seed）：**

| 配置 | BPB 均值 | 标准差 | loss 均值 |
|---|---|---|---|
| SP1024 | **0.77705** | 0.00089 | 1.27519 |
| SP4096 | **0.78732** | 0.01207 | 1.71725 |
| **Δ** | **+0.01027** | ±0.01288 | +0.44206 |

**预测不成立**：4096 的 BPB **更高**，且 **3 个 seed 方向不一致**（−0.00234 / +0.02795 / +0.00519）。
实测 loss 比 **1.3467** 越过阈值 **1.3291**，甚至高于均匀分布上界 **1.200**。

**解释**：loss 比高于均匀上界，说明 4096 在 6.55M tokens 下**没训起来**——
是"欠训练"实验，不是"收敛后"实验。**它不推翻官方榜单**（那 8 条在数 B tokens 规模上）。
完整分析见 `十三_C2G_ablation.md` 第三节·补。

**这次跑最值钱的产出**：4096 的 seed 方差是 1024 的 **13.6 倍** →
**它改变了 $25 的分配**（见第六节）。

## 五、复现

```bash
pip install torch sentencepiece numpy     # CPU 版即可

cd micro-benchmark
python scripts/prepare.py --pg-repo /path/to/parameter-golf-main --out data
python scripts/run_ablation.py --iters 800 --out out
```

> ⚠️ Windows 上路径含中文时，`sentencepiece` 会报 `NOT_FOUND`（**文件明明存在**）——
> 它的 C++ 层用 ANSI 码页打开文件。本包已用 `bpb.load_sentencepiece()` 绕开，
> **所有加载 tokenizer 的地方都必须走它**。

## 六、拿到算力后的第一批动作（**已被台架结果修正**）

```bash
# ① 复现基线，验证环境（~$4）
bash 十三_C2G_运行脚本_官方提交.sh baseline
# ② SP4096 × 4 seed（~$16）—— 台架显示方差是 1024 的 13.6 倍，必须拉信噪比
for s in 42 1337 2025 314; do bash 十三_C2G_运行脚本_官方提交.sh sp4096 $s; done
# ③ SP8192 × 1 seed 探路（~$4）—— 原计划 2 次，砍掉 1 次让给 SP4096
bash 十三_C2G_运行脚本_官方提交.sh sp8192 42
```

**$25 只够 6 次跑，所以筛选必须先在便宜的硬件上做完**（见《方案设计》第三节）。

> **这份分配跟最初写的草案不一样，是被台架数据改的。**
> 原来的想法是"SP4096 × 3 + SP8192 × 2"（覆盖两个方向）；
> 台架测出 4096 的 seed 标准差是 0.01207 → 3 个 seed 的均值标准误 ≈ 0.007，
> 而 Level 2 的判据是"比基线低 0.0444"——**如果真实效应只有 0.01~0.03，信噪比不够。**
> 所以把 SP8192 的预算挪一次给 SP4096，**改成"把信噪比拉起来"优先**。

失败预案见《方案草案》第四节；兜底方向是 depth recurrence。
